## Why the signing identity is not ad-hoc

An ad-hoc signature (`--sign -`) carries no certificate, so the designated
requirement macOS derives from it is `cdhash H"..."` — the hash of one exact
build. TCC stores that requirement when the user grants Accessibility, so the
next rebuild produces a different hash, stops matching, and the permission
silently stops applying **while the System Settings toggle still looks on**.
Re-toggling that stale entry cannot help; it has to be removed
(`tccutil reset Accessibility engineer.riteshrana.scrollwise`) and re-added.

Signing with a certificate yields `identifier "..." and certificate root =
H"..."` instead, which survives rebuilds — verified across four rebuilds and a
move to `/Applications` with no re-granting. `Scripts/build-app.sh` uses the
identity when present and falls back to ad-hoc with a warning, so the script
still works on a machine without it. The recreation recipe is a comment at the
signing block.

Two related traps, both hit during development:

- Launching the binary directly from Terminal makes the app inherit **Terminal's**
  Accessibility grant through TCC responsible-process attribution, so it reports
  "Accessibility granted" when the bundle has none. Only `open <bundle>` reports
  the real state.
- `SMAppService.mainApp.status` returns `.notFound` for an app that has never
  been registered, not `.notRegistered`. It is not a refusal — see
  `LoginItemState`.

## Migration note

`SettingsDefaults` shipped the tablet rule with `isEnabled: false`, and nothing
in the UI sets `DeviceRule.isEnabled`, so its Direction control could never be
switched on. The default is fixed, but a store written by an earlier build still
holds the disabled rule. There are no users yet, so no migration was written; if
that changes before release, add one.

## Known limitations, deliberate

1. **Rules act on device *class*, not individual device.** No public API attaches
   a device identifier to a `CGEvent` scroll event. Documented in the Devices
   pane in plain language rather than faked. This is the one place the
   implementation knowingly differs from the mockups.
2. **⌥⌘R is fixed.** A recorder UI is not implemented. If another app already
   owns the combination, registration fails, the app logs it and everything else
   continues working.
3. **Axis 3 and accelerated-delta fields are not flipped.** No shipping pointing
   device uses them; touching them would risk affecting unrelated input.
4. **Momentum is latched per gesture, not per device.** With two devices scrolled
   simultaneously the latch follows whichever gesture began first. Physically
   near-impossible for one user and not worth per-device state in the hot path.
